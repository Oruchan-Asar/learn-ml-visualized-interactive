<Hook>
  Last chapter's flow needed an invertible function, engineered by hand or by careful architecture
  choices, before it could define a density at all. What if a model didn't need to invert anything — just
  needed to know, at any point, which direction makes the data *more* likely?
</Hook>

<Intuition>
  <IntuitionDemo />

  Click "Take a Langevin step" a few times. The point starts at $x=-5$ — nowhere near the data — and
  drifts steadily toward $x=3$, the single peak of this chapter's target distribution, one gradient step
  at a time.
</Intuition>

<Formalize>
  The **score** of a distribution is $s(x) = \nabla_x \log p(x)$ — a vector field pointing toward higher
  density. For a Gaussian $\mathcal{N}(\mu,\sigma^2)$, it has a clean closed form:

  $$
  s(x) = \frac{d}{dx}\log p(x) = -\frac{x-\mu}{\sigma^2}
  $$

  <Variables>
    <Variable>**$s(x)$** — the score function: the gradient of the log-density, a vector field pointing toward higher-probability regions.</Variable>
    <Variable>**$p(x)$** — the probability density of the target distribution.</Variable>
    <Variable>**$\mu$** — the mean of the Gaussian target distribution.</Variable>
    <Variable>**$\sigma^2$** — the variance of the Gaussian target distribution.</Variable>
  </Variables>

  <Steps>
    <Step label="Climbing the score reaches the mode">
      Follow it uphill, repeatedly — $x \leftarrow x + \eta\, s(x)$ — and $x$ climbs toward $\mu$.
    </Step>
    <Step label="Langevin dynamics samples the whole distribution">
      Real score-based models add noise to this update (**Langevin dynamics**) so the process samples the
      *whole* distribution instead of always collapsing onto the single peak.
    </Step>
    <Step label="Learned directly, no invertibility required">
      A neural network is trained to estimate $s(x)$ directly from data, without ever needing an
      invertible architecture or a tractable normalizing constant.
    </Step>
  </Steps>
</Formalize>

<Play>
  <PlayDemo />

  Every bar here comes from a closed-form formula, not a simulation — the distance to the mode shrinks by
  exactly the same factor, $0.7$, every single step, no matter how far the trajectory started. That
  factor is $1 - \eta/\sigma^2$: it's baked into the step size and the target's own spread, not something
  that has to be measured empirically.
</Play>

<WorkedExample>
  Starting at $x_0=-5$, target $\mathcal{N}(3, 1)$, step size $\eta=0.3$:

  <Steps>
    <Step label="Step 1">
      $s(-5) = -(-5-3)/1 = 8$. $x_1 = -5 + 0.3(8) = -2.6$.
    </Step>
    <Step label="Step 2">
      $s(-2.6) = -(-2.6-3)/1 = 5.6$. $x_2 = -2.6 + 0.3(5.6) = -0.92$.
    </Step>
    <Step label="The distance to the mode obeys a clean pattern">
      $|x_0-3|=|-5-3|=8$, $|x_1-3|=|-2.6-3|=5.6$, $|x_2-3|=|-0.92-3|=3.92$ — each one is exactly $0.7\times$
      the last ($5.6/8=0.7$, $3.92/5.6=0.7$). That's not a coincidence of these particular numbers; it
      falls straight out of the fact that $s(x)$ is linear in $x$ for a Gaussian.
    </Step>
  </Steps>
</WorkedExample>

<Summary>
  $$
  x \leftarrow x + \eta\, \nabla_x \log p(x)
  $$

  This chapter's target was a single Gaussian precisely because its score has a closed form simple enough
  to hand-verify. Real score-based models estimate $s(x)$ with a neural network trained via *score
  matching* on complicated, multi-modal, high-dimensional data — where no closed form exists at all — and
  they run the noisy version of this update (not the deterministic climb shown here) so different starting
  points can land on different modes of the data, not just the nearest peak. The next chapter asks what
  happens if, instead of learning the score and *simulating* a path toward the data, a model is trained to
  predict the straight-line path itself.
</Summary>
