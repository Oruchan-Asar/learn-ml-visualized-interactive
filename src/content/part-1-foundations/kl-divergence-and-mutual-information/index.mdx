<Formalize>
  The **KL divergence** — short for **Kullback–Leibler divergence** — measures the extra bits it costs to
  describe data from $P$ using a code built for $Q$ instead of $P$'s own optimal code:

  $$
  D_{KL}(P \Vert Q) = \sum_x P(x) \log_2 \frac{P(x)}{Q(x)}
  $$

  <Variables>
    <Variable>**$D_{KL}(P\Vert Q)$** — the divergence itself, in bits: how many extra bits $Q$'s code wastes on data actually drawn from $P$.</Variable>
    <Variable>**$P(x)$** — the true probability of outcome $x$.</Variable>
    <Variable>**$Q(x)$** — the model's (or approximate) probability of that same outcome $x$.</Variable>
    <Variable>**$x$** — one outcome, ranging over everything either distribution assigns probability to.</Variable>
  </Variables>

  <Steps>
    <Step label="Never negative, zero only at a perfect match">
      $D_{KL}(P\Vert Q) \geq 0$ always, and it hits exactly $0$ only when $P=Q$ everywhere — the only way to
      waste zero bits on $Q$'s code is for $Q$ to already be the right code.
    </Step>
    <Step label="Not symmetric — direction matters">
      $D_{KL}(P\Vert Q) \neq D_{KL}(Q\Vert P)$ in general. Despite measuring how "far apart" two
      distributions are, swapping which one is the reference changes the answer, so it isn't a true distance.
    </Step>
    <Step label="Related to cross-entropy">
      **Cross-entropy** $H(P,Q) = -\sum_x P(x)\log_2 Q(x)$ always decomposes as
      $H(P,Q) = H(P) + D_{KL}(P\Vert Q)$ — Part II's cross-entropy loss chapter is exactly this $H(P,Q)$,
      with $P$ the true one-hot label.
    </Step>
  </Steps>
</Formalize>

<Play>
  <PlayDemo />

  Now watch both directions at once. $D_{KL}(P\Vert Q)$ and $D_{KL}(Q\Vert P)$ move together, roughly, but

</Play>

<WorkedExample>
  With $P=(0.5,0.3,0.2)$ and $Q=(0.4,0.4,0.2)$:

  <Steps>
    <Step label="KL divergence, one direction">
      $D_{KL}(P\Vert Q) = 0.5\log_2\frac{0.5}{0.4} + 0.3\log_2\frac{0.3}{0.4} + 0.2\log_2\frac{0.2}{0.2}
      \approx 0.0365$ bits. The third term is exactly $0$ since $P$ and $Q$ agree there.
    </Step>
    <Step label="The reverse direction gives a different number">
      $D_{KL}(Q\Vert P) = 0.4\log_2\frac{0.4}{0.5} + 0.4\log_2\frac{0.4}{0.3} + 0.2\log_2\frac{0.2}{0.2}
      \approx 0.0372$ bits — close to the forward value here, but not identical, confirming the asymmetry.
    </Step>
    <Step label="Mutual information: KL applied to independence itself">
      For a joint distribution over two binary variables, $P(X{=}0,Y{=}0){=}P(X{=}1,Y{=}1){=}0.4$ and
      $P(X{=}0,Y{=}1){=}P(X{=}1,Y{=}0){=}0.1$ — $X$ and $Y$ agree far more than chance. Both marginals are
      uniform, $(0.5,0.5)$, so $H(X)=H(Y)=1$ bit, while the joint entropy $H(X,Y)\approx1.7219$ bits.
      **Mutual information** is exactly the gap: $I(X;Y)=H(X)+H(Y)-H(X,Y)\approx 0.2781$ bits — equivalently,
      it's the KL divergence between the real joint distribution and the independent one its own marginals
      would predict. Zero mutual information means knowing $X$ tells you nothing about $Y$; here, it tells
      you a fair amount.
    </Step>
  </Steps>
</WorkedExample>

<KLCheckpoint />

<Summary>
  $$
  D_{KL}(P\Vert Q) = \sum_x P(x)\log_2\frac{P(x)}{Q(x)} \qquad\qquad I(X;Y) = \sum_{x,y} P(x,y)\log_2\frac{P(x,y)}{P(x)P(y)}
  $$

  KL divergence is entropy's natural extension to *comparing* two distributions instead of describing one;
  mutual information is what happens when you apply that same comparison to a joint distribution against
  the independent version of itself. Both show up constantly downstream — in cross-entropy loss, in
  variational autoencoders' regularizer, and in feature-selection methods that rank inputs by how much
  information they share with the target.
</Summary>
