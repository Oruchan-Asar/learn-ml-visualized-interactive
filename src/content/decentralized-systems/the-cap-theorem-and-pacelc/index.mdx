<Formalize>
  During a network **partition**, there is no third option:

  <Steps>
    <Step label="CP">
      Refuse to answer unless you can prove you have the latest write. Cut off, you can't prove it — so you
      block or error. Consistency is preserved; availability is not.
    </Step>
    <Step label="AP">
      Always answer with whatever you have locally. Availability is preserved; the answer might be stale.
    </Step>
  </Steps>

  **PACELC** extends this past the partition case: even with no partition (the "Else" branch), a system still
  trades **Latency** against **Consistency** — confirming a write with every replica synchronously raises
  consistency but costs latency, and vice versa.

  $$
  \text{label} = P\{C \mid A\} \,/\, E\{C \mid L\}
  $$

  <Variables>
    <Variable>**P** — the partition-time choice: Consistency or Availability.</Variable>
    <Variable>**E** — the normal-time ("Else") choice: Consistency or Latency.</Variable>
  </Variables>
</Formalize>

<Play>
  <PlayDemo />

  Toggle both axes independently and watch `pacelcLabel` produce one of the four canonical two-letter-pair
  labels — then see whether it matches any of the three example systems below.
</Play>

<WorkedExample>
  <Steps>
    <Step label="CP, applied to R2">
      `resolveDuringPartition(STALE_PARTITION_SCENARIO, "CP")` returns responds = false, value = null, consistent =
      true. No answer, but no risk either.
    </Step>
    <Step label="AP, applied to R2">
      `resolveDuringPartition(STALE_PARTITION_SCENARIO, "AP")` returns responds = true, value = 1, consistent =
      false. An answer, but a stale one — R2's local value hasn't caught up.
    </Step>
    <Step label="Classifying real systems">
      - Dynamo/Cassandra: chooses Availability during a partition ($P{=}A$) and Latency otherwise
        ($E{=}L$) → <strong>PA/EL</strong>
      - A majority-write MongoDB: chooses Consistency during a partition ($P{=}C$) but Latency
        otherwise ($E{=}L$) → <strong>PC/EL</strong>
      - A fully-synchronous SQL cluster: chooses Consistency both times ($P{=}C$, $E{=}C$) →
        <strong>PC/EC</strong>
    </Step>
  </Steps>
</WorkedExample>

<CapTheoremCheckpoint />

<Summary>
  $$
  \text{label} = P\{C \mid A\} \,/\, E\{C \mid L\}
  $$

  CAP says a partition forces a binary choice between Consistency and Availability — there's no way around it.
  PACELC adds the other half of the story: even when nothing is broken, every system is still trading Latency
  against Consistency, and that choice is exactly as real as the partition-time one.
</Summary>
