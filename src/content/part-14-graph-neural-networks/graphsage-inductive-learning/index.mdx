</Hook>

<Formalize>
  **GraphSAGE** ("SAmple and aggreGatE") changes two things about the previous chapter's **GCN** (short for
  **Graph Convolutional Network**). First, it aggregates a **fixed-size random sample** of neighbors
  instead of all of them — bounded work per node, no matter how high the degree gets:

  $$
  h_v^{(k+1)} = \text{AGGREGATE}\Big(h_v^{(k)}, \; \{h_u^{(k)} : u \in \text{SAMPLE}(\mathcal{N}(v), K)\}\Big)
  $$

  <Variables>
    <Variable>**$h_v^{(k)}$** — node $v$'s feature after $k$ rounds of message passing.</Variable>
    <Variable>**$h_v^{(k+1)}$** — node $v$'s updated feature after one more round.</Variable>
    <Variable>**$h_u^{(k)}$** — a sampled neighbor $u$'s current feature.</Variable>
    <Variable>**$\mathcal{N}(v)$** — node $v$'s full neighborhood, before sampling.</Variable>
    <Variable>**SAMPLE($\mathcal{N}(v), K$)** — a fixed-size random draw of $K$ neighbors from $v$'s full neighborhood.</Variable>
    <Variable>**$K$** — the sample size: how many neighbors get aggregated, regardless of how many actually exist.</Variable>
    <Variable>**AGGREGATE** — the learned combining function, applied to any neighborhood, seen or unseen.</Variable>
  </Variables>

  Second — and this is the bigger idea — it learns an aggregation *function*, not a per-node lookup
  table. A method that memorizes one embedding vector per node (like node2vec) is **transductive**: it
  has nothing to say about a node it never saw. GraphSAGE's function takes *any* neighborhood as input, so
  it's **inductive**: hand it a brand-new node's neighborhood and it produces an answer immediately.
</Formalize>

</Play>

<WorkedExample>
  With sample size $K=2$ (always take the two lowest-numbered neighbors, standing in for a random draw):

  <Steps>
    <Step label="A low-degree node: sampling changes nothing">
      Node $0$ has exactly two neighbors, $\{1,2\}$ — sampling two out of two keeps everything. Sampled
      mean $=\frac{1+2+0}{3}=1.0$, identical to the full mean.
    </Step>
    <Step label="A high-degree node: sampling genuinely loses information">
      Node $1$ has three neighbors, $\{0,2,3\}$. Sampling keeps only $\{0,2\}$, dropping neighbor $3$
      (feature $3$). Sampled mean $=\frac{2+1+0}{3}=1.0$; the true full-neighborhood mean is
      $\frac{2+1+0+3}{4}=1.5$ — a real, measurable gap, the price of bounding the work per node.
    </Step>
    <Step label="A node that never existed during training">
      A new node with feature $4$, connected only to node $0$ (feature $1$): its aggregate is
      $\frac{4+1}{2}=2.5$, using *the same function* as every original node — no new parameters, no
      retraining pass, just one more function call.
    </Step>
  </Steps>
</WorkedExample>

<Summary>
  $$
  h_v^{(k+1)} = \text{AGGREGATE}\Big(h_v^{(k)}, \{h_u^{(k)} : u\in\text{SAMPLE}(\mathcal{N}(v),K)\}\Big)
  $$

  Sampling trades a little accuracy for a hard cap on cost per node — essential once "neighbor count" can
  be in the thousands. Being inductive is the deeper payoff: any model built to *learn a function of a
  neighborhood* generalizes to graphs it's never seen, the same way a CNN's learned filters generalize to
  images it's never seen. The next chapter asks whether "sample K neighbors and average them equally" is
  really the best way to combine them — or whether some neighbors should just count for more.
</Summary>
