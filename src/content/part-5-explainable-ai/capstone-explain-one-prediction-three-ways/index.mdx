<Hook>
  Four chapters, four different answers to "why did the model say that." Applied to the exact same house, the exact same linear model, do they actually agree with each other — or is each one answering a subtly different question?
</Hook>

<Intuition>
  <IntuitionDemo />

  Same house from Chapter 6: size $25$, age $5$, distance $8$, renovated. Switch lenses. Saliency reports the raw weight magnitudes — the same four numbers no matter which house you ask about. SHAP reports each feature's actual pull on *this* house's price, relative to a typical one. Counterfactual reports something else again: how much each feature would have to move to flip an approve/deny decision.
</Intuition>

<Formalize>
  All three read the same four weights $w$, but ask three different questions:

  $$
  \text{saliency}_i = |w_i|, \qquad \text{SHAP}_i = w_i(x_i-\bar x_i), \qquad \Delta^{\text{cf}} = -\frac{f(x)}{\lVert w \rVert^2}\,w
  $$

  Saliency answers "how sensitive is the output to this feature, in general." SHAP answers "how much did this feature's *actual value* move this prediction away from typical." Counterfactual answers "what's the cheapest edit that changes the *decision*." None of them is wrong — they're just not the same question, and mixing them up is a real, common mistake.
</Formalize>

<Play>
  <PlayDemo />

  Compare this house to the baseline house — a very different prediction, $445$ versus $320$. Saliency's bars don't move at all: they never looked at either house's actual values, only the model's fixed weights. SHAP's bars do move, because SHAP's entire job is measuring how far *this instance* sits from typical.
</Play>

<WorkedExample>
  This house predicts $445$; call anything below a $500$ threshold "not yet approved" for this exercise:

  <Steps>
    <Step label="Saliency says renovated matters most">
      $|w| = (15, 2, 5, 20)$ for size, age, distance, renovated — renovated's raw sensitivity is the largest
      of the four, and that ranking would be identical for every house this model ever sees.
    </Step>
    <Step label="SHAP ranks size highest instead">
      For this specific house, size contributes $75$ and renovated contributes $20$ — size dominates here,
      because this house's size is $5$ units above baseline while its renovated status only differs by $1$.
    </Step>
    <Step label="The counterfactual finds a different answer again">
      The nearest edit that reaches the $500$ threshold moves size by about $+1.26$, age by $-0.17$, distance
      by $-0.42$, and renovated by about $+1.68$ — and that last number is a real problem: renovated is a
      $0/1$ feature, and $1.68$ isn't a valid value for it. The naive closed form doesn't know that
      "renovated" can't be anything other than $0$ or $1$.
    </Step>
  </Steps>
</WorkedExample>

<Summary>
  $$
  \text{saliency}_i = |w_i|, \qquad \text{SHAP}_i = w_i(x_i-\bar x_i), \qquad \Delta^{\text{cf}} = -\frac{f(x)}{\lVert w \rVert^2}\,w
  $$

  Every explanation technique in this part traces back to the same handful of ideas from earlier in the course: a derivative (saliency, Grad-CAM), a weighted local fit (LIME), a fair game-theoretic split (Shapley, SHAP), and a gradient step toward a boundary (counterfactuals). None of them is "the" explanation — each answers a genuinely different question about the same model, and picking the right one means knowing which question you're actually asking. That's the real skill this part was building toward: not running an explainability library, but knowing what its output does and doesn't tell you. Explainability comes back for a second, deeper pass later in the course, once there are less transparent models — and a wider roster of architectures — actually worth auditing.
</Summary>
