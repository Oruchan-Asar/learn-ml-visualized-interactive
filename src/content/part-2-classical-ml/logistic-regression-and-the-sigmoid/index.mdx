<Hook>
  Linear regression outputs any number at all. What if the answer you actually want is a probability — something that has to stay between 0 and 1?
</Hook>

<Intuition>
  <IntuitionDemo />

  Drag the point along the curve. Near the middle it swings quickly from "probably not" to "probably so" — but far to either side, it barely moves at all, no matter how much further you drag.
</Intuition>

<Formalize>
  That S-shaped squashing function is the **sigmoid** —

  $$
  \sigma(z) = \frac{1}{1 + e^{-z}}
  $$

  <Variables>
    <Variable>**$\sigma(z)$** — the sigmoid function: squashes any real number into a probability between 0 and 1.</Variable>
    <Variable>**$z$** — the raw input score being squashed, before it's turned into a probability.</Variable>
  </Variables>

  <Steps>
    <Step label="Applied to the same linear score">
      Feed in the same linear score from Chapter 1 of this part, $z = wx + b$. Together, $\sigma(wx+b)$ turns any
      real number into a valid probability.
    </Step>
    <Step label="Where it crosses 0.5 is the decision boundary">
      The point where $\sigma(wx+b)$ crosses exactly $0.5$ — where $wx+b=0$ — is the **decision boundary**.
    </Step>
  </Steps>
</Formalize>

<Play>
  <PlayDemo />

  Drag $w$ and $b$ and watch the boundary itself move: $b$ shifts it sideways, $w$ controls how sharply the curve turns from 0 to 1 around it.
</Play>

<WorkedExample>
  With $w=1, b=-5$:

  <Steps>
    <Step label="Evaluate at x = 5">
      $z = 1(5) + (-5) = 0$, so $\sigma(0) = 0.5$ exactly — the boundary.
    </Step>
    <Step label="Evaluate at x = 8">
      $z = 1(8) + (-5) = 3$, so $\sigma(3) \approx 0.953$ — confidently on the "yes" side.
    </Step>
  </Steps>
</WorkedExample>

<Summary>
  $$
  \sigma(z) = \frac{1}{1+e^{-z}}, \qquad z = wx+b
  $$

  Logistic regression is linear regression's score, squashed into a probability. Its derivative is exactly the chain rule from Part I — $\sigma$ applied to a line, differentiated as $\sigma'(z)\cdot w$. Next: the loss function built specifically for this kind of output.
</Summary>
